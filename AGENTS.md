# MetroPulse — Agent Context

## Project
Mobility-intelligence desk for Indian cities (Pulse, Alerts, Siting, Briefing; runs in the browser) plus the India Twin and a planning agent. Next.js 14 (frontend) + FastAPI (backend) + optional Supabase PostgreSQL + pgvector.

## Commands
- Backend: `cd backend && uvicorn app.main:app --reload --port 8000`
- Twin data: `cd backend && python scripts/twin_build.py check|build`
- Backend tests: `cd backend && pytest tests/unit tests/integration` (929 tests; needs `python -m spacy download en_core_web_sm`)
- Frontend: `cd frontend && npm run dev`
- Frontend tests: `cd frontend && npm run test` (311 Jest tests; CI uses `npm run test:ci`; locally under a memory cap use `npx jest --maxWorkers=1`)
- End-to-end: `cd frontend && npm run build && npm run e2e` (Playwright, Chromium; `npm run e2e:install` once). Build with `NODE_OPTIONS=--max-old-space-size=2048` on small machines
- Lint/typecheck: `cd frontend && npm run lint && npm run type-check`

## Desk (the product surface)
- Routes: `/` landing, `/desk` (Pulse, Alerts, Siting with Stop/Line modes; URL holds `city`, `tab`, `incident`, `suggest`, `s` (an encoded line) or `scenario` (a saved id)), `/brief?city=&s=`, `/compare?city=&a=&b=`, `/city/{id}` (30 static pages), `/developers`, `/privacy`, `/twin` (India Twin map), `/api/v1/*` (JSON API, Next route handlers)
- Engines (pure TypeScript, run in the browser): `frontend/src/lib/pulse/{geo,model,alerts,siting,scenario,calibrate,summary,alternatives}.ts`, parsers in `lib/pulse/import/`, browser stores in `userdata.ts` and `scenarioStore.ts`; each with a `.test.ts`
- Your data: parsed in the browser, derived data only in `localStorage`; never add an upload endpoint (ADR 0002). Without data the model must stay bit-identical to 1.x (pinned in `model.test.ts`)
- City data: `frontend/src/data/cities.json`, generated by `python scripts/export_sample_cities.py` from `data/cities/*.yaml`
- Product docs: `docs/PRODUCT.md`, `docs/DEMO.md`. The desk runs on a synthetic sample model and must always say so on screen

## India Twin
The legacy city simulator is retired (pre-change state: git tag `legacy-metropulse`). The product is now the India Twin: a sourced map of Indian places and indicators.
- Spec: `docs/superpowers/specs/2026-10-18-india-twin-design.md`; data source notes in `docs/twin/DATA_SOURCES.md`
- Backend package: `backend/twin/` (engine-style: never imports from `app/`); API in `backend/app/routes/twin.py` (`/api/twin/*`)
- Built data: `data/twin/` (produced by `scripts/twin_build.py`)
- Frontend: `frontend/src/components/twin/`, `store/twinStore.ts`, `lib/twinApi.ts`, `types/twin.ts`
- Parked for M2 (not wired to the UI): `engine/agent/` (served by the token-gated `/ws/agent`; frontend client: `components/agent/AgentChat.tsx`), `app/realtime*`; `engine/nl_engine/` is live (it backs the agent's scenario parser); legacy city YAMLs in `data/cities/` still back `/api/regions*`

## Security

### Path Traversal Sanitization
`CityConfig.load()` and `CityConfig.load_geojson()` validate `city_name` with `re.fullmatch(r'[a-zA-Z0-9_]+', city_name)` to prevent directory traversal attacks. The simulator's `grid.py` is gone (2.0.0); the twin's file paths are validated in `backend/twin/`.

### WebSocket Auth and Connection Limit
`/ws/agent` is the only WebSocket endpoint (`app/ws/agent.py`, mounted in `app/main.py`). It is **disabled unless `AGENT_WS_TOKEN` is set**; clients send the token as `?token=` or `Authorization: Bearer`, compared with `hmac.compare_digest`. Bad/missing token closes with 1008 before accept. At most `WS_MAX_CONNECTIONS` (default 10) concurrent sessions; extras close with 1013. Client-facing errors are generic (no exception text). Tests: `tests/integration/test_ws_agent.py`. Supabase-Auth-based per-user auth (spec §4) is still to do; the shared token is the interim gate.

### Ingest Token
`POST /api/ingest` is open by default. If `INGEST_TOKEN` is set it requires `Authorization: Bearer <token>` or `X-Ingest-Token: <token>` (constant-time compare, 401 otherwise); see `require_ingest_token` in `app/routes/realtime.py`. Tests: `tests/integration/test_api_routes.py`.

### Tests Never Touch the Network
`backend/tests/conftest.py` blanks Supabase/LLM settings (env beats `.env`) and patches `socket.getaddrinfo`/`connect` to loopback only; any other attempt fails the test at teardown, even if the code swallowed the error. Mock HTTP with `httpx.MockTransport` (see `tests/unit/test_realtime.py`). Mark a deliberate live test with `@pytest.mark.allow_network`.

## Request Middleware (`backend/app/middleware.py`)
- REST routes stay under `/api` (the June `/api/v1` prefix was not adopted; every desk, twin and agent client uses `/api`).
- `CorrelationIdMiddleware`: every response carries `X-Request-ID` (a well-formed client value is echoed, otherwise a UUID).
- `RequestLoggingMiddleware`: one JSON log line per request (`method`, `path`, `status`, `response_time_ms`, `request_id`); health checks (`/api/health`, `/api/health/data`, `/api/health/llm`) are skipped and bodies are never logged. `app/logging_setup.py` gives the `app` logger a JSON stderr handler at `LOG_LEVEL` and redacts `token=` (and `q=` on the access log) from `uvicorn.error`/`uvicorn.access`.
- `RateLimitMiddleware`: `RATE_LIMIT_PER_MINUTE` per IP, keyed on `Fly-Client-IP` when present (default 240, `0` disables; tests and `scripts/bench_api.py` runs need 0). `POST /api/ingest` also has its own 3/min limit on top of `INGEST_TOKEN`.
- `GET /api/health/llm` says which LLM providers have credentials set, without calling them or echoing keys.

## Conventions
- Python: Use NumPy vectorized ops where arrays are involved
- TypeScript: strict mode, camelCase props, PascalCase components
- All API responses use `{ success, data, error, meta }` envelope
- Commit format: `type(scope): description` (e.g. `feat(twin): add place index`)
